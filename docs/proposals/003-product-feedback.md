# 003 기획 피드백과 추가 기능

## 한눈에 보기

**문제**

- 16개 Phase를 다 만들어야 사용자 반응을 볼 수 있고, 의욕이 낮은 사용자에게 시작 장벽(키트 구매·배송 대기)과 기록 부담이 크다.
- 문구·지지 모드 기준·위기 키워드가 모두 "전문가 검토 후 확정"인데, 구현 계획에 검토 시점이 없다.

**제안**

- MVP(Phase 2·3·4·5·9 + 8 일부)로 먼저 비공개 테스트를 하고 나머지를 진행한다.
- 키트 없이도 시작할 수 있게 하고(배송 대기 모드, 집 채소 Lv.0), 기분 기록을 가볍게 한다.
- 지지 모드를 보완하고 나만의 안전 계획 카드를 더하며, 전문가 검토 일정을 Phase 3 전후로 넣는다.

**결정해 주셨으면 하는 것**

1. 1번 MVP 범위, 비공개 테스트 규모와 기간
2. 2번 시작 장벽: 배송 대기 모드(A)·집 채소 Lv.0(B) 채택 여부와 Lv.0 종 목록
3. 3번 기분 기록: 척도와 묻는 빈도 (전문가 의견 필요)
4. 5·6번 지지 모드 보완과 안전 계획 카드 채택 여부 (전문가 검토 필수)
5. 13번 전문가 검토: 검토자, 시점, 범위

아래는 항목별 상세입니다.

## 상태

- 상태: 검토 중
- 작성일: 2026-11-09
- 범위: 001(가치·계획), 002(구조)에서 다루지 않은 기획 의견을 모았다.

## 0. 지켜야 할 장점

- **원칙을 자동 검사로 강제:** 금지 문구 검사기, 줄지 않는 카운터, 서버만 쓰는 판독 결과.
- **연속 기록(streak) 없음:** 누적 돌본 날과 주간 정원만 써서, 놓친 날이 자기비난의 재료가 되지 않는다.
- **문구를 데이터로 분리:** 전문가 검토와 수정을 개발과 따로 할 수 있다.
- **안전장치를 처음부터 설계:** 잠금화면 문구 제한, 기기 안 키워드 감지, 지지 모드.
- **모형이 퇴보하지 않음:** 실제 새싹이 망가져도 화면 속 새싹은 시들지 않는다.

## 1. MVP 범위를 먼저 검증 [높음 / Phase 전체 / 전문가 검토 없음]

- **문제:** 16개 Phase를 순서대로 다 구현해야 사용자 반응을 볼 수 있다. 핵심 가설("새싹 돌봄과 짝지은 작은 행동이 실제 행동과 기분 변화를 늘리는가")을 확인하는 데 친구 기능, 레벨, 알림 학습, 홈 위젯은 필요 없다.
- **제안:** MVP = Phase 2(온보딩) + 3(홈·행동) + 4(모형, 단순하게) + 5(카메라, AI는 이슈 감지 위주) + 9(안전장치) + 8 일부(아침·저녁 알림 2개). 이 상태로 비공개 테스트를 해서 행동 완료율과 1~2주 뒤 재방문을 본 다음 나머지를 진행한다. 001의 활동 계획은 MVP에 "다른 일 다음" 방식만 넣는다. 알림 없이 새싹 체크인 때 다시 보여주므로 Phase 8 없이도 작동한다. 시간 방식 계획과 계획 알림은 Phase 8 전체 구현 때 넣는다.
- **정할 것:** MVP 범위, 비공개 테스트 규모와 기간.

## 2. 시작 장벽 낮추기 [높음 / Phase 2, 4, 5 / 전문가 검토 없음]

- **문제:** 지금 흐름은 "키트 구매 → 배송 대기 → 설치"다. 의욕이 낮은 사람이 "키트를 먼저 사세요"를 들으면 2~3일 배송 동안 대부분 이탈한다. 돈을 써야 시작할 수 있다는 점도 부담이다.
- **제안 A (배송 대기 모드):** 키트가 오기 전 며칠은 "새싹 자리 정하기", "물 담을 컵 꺼내두기" 같은 준비 행동만으로 하루 루프를 돌린다. 행동 기록은 이때부터 쌓인다.
- **제안 B (집 채소 다시 키우기, Lv.0):** 대파 뿌리, 무 꼭지, 양파처럼 집에 늘 있는 자투리를 물에 꽂아 다시 키운다. 흐름: 키트 선택에서 "아직 없어요" → [키트 추천 보기] / [집에 있는 걸로 먼저 시작하기] → 종류 선택 → 물꽂이 안내 → 바로 루프 시작 → 첫 챕터를 마치면 새싹 키트를 부드럽게 제안. 새싹용 성장 단계(떡잎 기준)와 판독 프롬프트의 단계 목록은 그대로 쓸 수 없다. Lv.2 스킨답서스처럼 `levels.json`에 자체 성장 단계와 프로필을 두는 방식이 필요하다.
- **정할 것:**
  - A·B 채택 여부, Lv.0 종 목록
  - Lv.0 종을 `species.json`에 둘지, Lv.2처럼 `levels.json`에 따로 둘지
  - Lv.0의 성장 단계를 어떻게 정의할지
  - Lv.0은 AI 판독 없이 날짜 기준으로만 모형을 그릴지

## 3. 기분 기록 부담 줄이기 [높음 / Phase 3 / 전문가 검토 필요]

- **문제:** 1분짜리 "물 한 컵 마시기"에 행동 전 5점 척도 → 행동 → 행동 후 5점 척도까지 여러 번 탭해야 한다. 행동보다 기록이 무겁다. 앱이 "해보면 나아져요"라고 계속 말하면 점수를 맞춰 올려 적는 응답 편향이 생길 수 있다.
- **제안:** 행동 전 기분은 선택으로 하고 에너지 체크 값으로 대신한다. 5점 척도 대신 이모지 3개 정도로 한 번에 탭한다. 행동 후 기분도 매번 묻지 않고 가끔(예: 하루 첫 행동만) 묻는다. "나를 살리는 행동 Top 3" 계산에는 충분하다.
- **맞바꿈:** 기분을 덜 물으면 가중치 판단의 근거도 줄어든다. 001 A-3의 7일 가중치 하향은 행동 전후 기분이 둘 다 기록된 행동에만 적용한다.
- **정할 것:** 척도, 묻는 빈도. (전문가 의견 필요)
- **001과의 연결:** 001의 계획 알림에서 "다녀왔어요" 뒤에 기분을 매번 물을지가 이 결정을 따른다.

## 4. AI 판독의 역할과 비용 [중간 / Phase 5 / 전문가 검토 없음]

- **문제:** 6.1 결합 규칙상 AI 단계는 신뢰도가 낮으면 무시되고, 앞서가면 제한되고, 뒤로는 못 간다. 표시 단계는 대부분 날짜 기대값으로 정해지고, AI가 실제로 기여하는 건 이슈 감지(곰팡이, 마름, 웃자람)다. 하루 6회 제한은 넉넉하다.
- **제안:** 하루 판독 횟수를 1~2회로 줄이고 사용자 수에 비례하는 API 비용을 미리 계산한다. 프롬프트 우선순위를 이슈 판정에 둔다. 사진을 올리자마자 날짜 기대값으로 모형을 먼저 그리고, 판독 결과가 오면 보정한다.
- **정할 것:** 하루 횟수, 월 예산 상한(CLAUDE.md 11절에 이미 미결로 있음).

## 5. 지지 모드 보완 [높음 / Phase 9 / 전문가 검토 필요]

- **문제:** 위기 키워드가 단순 포함 검사라서 "그만하고 싶다", "다 놓고 싶어", "죽 고 싶" 같은 띄어쓰기 변형·오타는 놓치고, "웃겨 죽을래", "배고파 죽고 싶음"은 잘못 잡는다. 또 7일 미접속 시 알림을 끝까지 멈추는 규칙은 상태가 가장 나빠진 사람이 조용히 사라지는 시점과 겹친다.
- **제안:** 최소한 공백을 지우고 비교하는 정규화를 넣는다. 잘못 잡았을 때는 안내 시트를 부드럽게 닫을 수 있게 이미 설계되어 있으므로("괜찮아요, 닫을게요"), 놓치는 쪽을 줄이는 방향이 낫다. 7일 미접속 문제는 앱이 재촉할 일이 아니므로 6번(안전 계획 카드)으로 보완한다.
- **정할 것:** 정규화 방식, 키워드 목록 (전문가 검토).

## 6. 나만의 안전 계획 카드 [높음 / Phase 9 / 전문가 검토 필요]

- **문제:** 도움받기 화면은 외부 기관(109, 마들랜 SNS 상담, 119)만 안내한다.
- **제안:** 자살예방 분야에서 근거가 있는 안전 계획(Safety Planning) 방식으로, 상태가 괜찮을 때 사용자가 직접 미리 적어두는 카드를 만든다. 항목: ① 내가 힘들어질 때 나타나는 신호 ② 혼자 해볼 수 있는 것(앱에서 기분이 올랐던 행동을 Top 3 데이터로 자동 추천) ③ 연락할 수 있는 사람(연락처에서 선택 → 전화·문자 바로가기) ④ 전문 기관(기존 109·119).
- 설정에서, 또는 지지 모드 진입 시 부드럽게 제안하고 건너뛸 수 있다. 도움받기 화면 맨 위에 "내가 적어둔 카드"로 보여준다. 내용은 기기에만 저장하고, 문항은 전문가 검토를 받는다.

## 7. 알림에서 바로 완료 [중간 / Phase 8 / 전문가 검토 없음]

- **문제:** 이 앱의 성공 기준은 "앱을 닫고 행동하는 것"인데, 지금은 알림을 누르면 앱이 열린다.
- **제안:** 아침 알림("아침 물 갈 시간이에요 💧")에 [물 갈았어요] [지금은 괜찮아요] 버튼을 단다. [지금은 괜찮아요]를 누르면 알림만 닫히고, 계획을 만들지 않으며, 기록도 남기지 않는다. 001의 "나중에 할게요"(계획을 만드는 버튼)와는 다른 동작이다. 앱을 열지 않고 행동 기록과 돌본 날이 쌓인다. 기분은 묻지 않는다. 알림 학습의 보상 신호(`actionWithin2h`)도 더 깨끗하게 모인다.
- **001과의 연결:** 001의 계획 알림 버튼([다녀왔어요] [30분 뒤로] [오늘은 넘길게요])과 같은 방식이다.

## 8. 내 미션 만들기 [중간 / Phase 3 이후 / 전문가 검토 없음]

- **문제:** 기본 사다리 5개로는 개인 생활을 다 담을 수 없다("기타 5분 치기", "과제 파일 열기만 하기").
- **제안:** 행동 제안 화면 하단 "내 행동 추가" → 행동 입력 → 에너지 수준 선택 → (선택) "더 작게 쪼개볼까요?" 도움 화면 → 내 사다리로 저장 → 기존 사다리와 같은 규칙으로 제안. 001의 가치 태그도 사용자가 고른다.
- 주의: 사용자 입력 문구는 금지 문구 검사를 할 수 없으므로 위기 키워드 검사 대상에 넣는다. 쪼개는 일을 AI로 하면 1절 4번과 충돌하므로, 사용자가 직접 쪼개게 돕는 화면으로만 만든다. 사용자가 직접 쓴 미션 문구는 알림 본문에 넣지 않는다. 이런 미션의 계획 알림은 `messages.json`의 일반 문구(예: "정해둔 시간이에요 🌱")를 쓰고, 미션 이름은 앱을 열었을 때만 보여준다. 이렇게 1절 4번과 8번을 모두 지킨다. MVP 다음에 한다.

## 9. 상담 받을 때 보여줄 기록 요약 [낮음 / Phase 16 / 전문가 검토 필요]

- **문제:** 상담실에서 "요즘 어땠어요?"에 답하기 어려운 사람이 많다. 웰니스 앱이 할 수 있는 좋은 일 중 하나가 전문 도움으로 이어주는 것이다.
- **제안:** 설정 → 기록 요약 만들기 → 기간 선택 → 돌본 날, 에너지 분포, 기분 추이, 자주 한 행동, 기분이 올랐던 행동 → PDF나 이미지로 저장·공유. Phase 16 데이터 내보내기와 함께 만든다.
- 주의: "진단", "증상" 같은 표현이나 해석 문구 없이 기록만 요약한다. 의료기기로 보이면 안 된다.

## 10. 기분 데이터 기기에만 저장 옵션 [낮음 / 출시 후 / 전문가 검토 없음]

- **문제:** 지금은 민감정보 처리에 동의하지 않으면 앱을 아예 쓸 수 없다.
- **제안:** 동의를 망설이는 사용자에게 [서버에 백업] / [이 기기에만 저장] 선택지를 준다. 기기에만 저장하면 기기를 바꿀 때 기록이 사라진다고 안내한다. 구조가 복잡해지므로 출시 후 순위다.
- **정할 것:** 이 옵션을 고르면 지지 모드 판정은 기기에서 한다(002 2번의 예외).

## 11. 빛 부족 대응 [낮음 / Phase 5, 10 / 전문가 검토 없음]

- **문제:** 실내 새싹의 가장 흔한 실패는 웃자람(빛 부족)이고, 겨울이나 북향 원룸이면 거의 피할 수 없다. 이 앱에서 식물의 실패는 사용자의 실패감으로 이어지기 쉽다.
- **제안:** 판독에서 `leggy`나 `yellowing`이 반복되면 "이 자리는 빛이 조금 부족한 것 같아요"와 자리 옮기기 안내 → 그래도 반복되면 키트 추천에서 소형 식물등 안내.

## 12. 알림 문구 학습(Thompson Sampling) 재검토 [낮음 / Phase 14 / 전문가 검토 없음]

- **문제:** 사용자 한 명이 받는 알림은 하루 1~3개이고 보상("2시간 안에 해봤어요")도 드물어, 사용자별 분포가 의미 있게 갈라지려면 몇 달이 걸린다. "누르게 만드는 문구"를 최적화하는 것은 "압박하지 않는다"는 원칙과 미묘하게 부딪힐 수 있다.
- **제안:** 하려면 전체 사용자 데이터로 공통 사전분포를 만들고 사용자별로 조금씩 보정하는 계층형 구조로 한다. 출시 초기에는 빼도 잃을 게 거의 없으므로 보류를 제안한다.
- **002와의 연결:** 002 1번 엔진 표의 8번째 엔진(알림 문구 학습, 6.9)이 이 항목이다.

## 13. 전문가 검토 일정 [높음 / Phase 3 전후 / 해당 없음]

- **문제:** 문구, 지지 모드 기준, 위기 키워드가 전부 "전문가 검토 후 확정"인데 구현 계획(CLAUDE.md 8절)에 검토 시점이 없다. 이게 끝나야 출시할 수 있다.
- **제안:** Phase 3 전후로 한 번 검토를 받는 일정을 넣는다. 창구 후보: 대학 상담센터, 정신건강복지센터, 임상심리 전공 대학원생.
- **정할 것:** 검토자, 시점, 검토 범위(001·003의 새 문구 포함).
